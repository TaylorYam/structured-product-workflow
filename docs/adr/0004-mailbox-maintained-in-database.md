# 0004: 信箱改由資料庫直接維護／Maintain the Mailbox Directly in the Database

- 狀態／Status: Accepted
- 日期／Date: 2026-10-19
- 追蹤／Tracking: #35
- 取代／Supersedes: [ADR 0003](0003-minimal-fcn-database.md) 中「信箱以 `信箱.xlsx` 整份更新」一條／the "refresh people wholesale from `信箱.xlsx`" bullet of ADR 0003

## 繁體中文

### 背景

ADR 0003 讓每日匯入同時讀 `信箱.xlsx`，每次整份取代 `mailbox` 的人員。實際上信箱很少變動，每天多選一個檔案沒有幫助，還可能因為選錯檔案而覆蓋人員資料。使用者偏好直接用 SQL 維護。

### 決策

- `mailbox.person`、`mailbox.alias` 由使用者直接在資料庫維護（例如 pgAdmin），不再從 Excel 匯入。
- 每日匯入只讀 `每日更新.xlsx`，不修改 `mailbox`，只拿它比對 FC 名字；信箱是空的時候提醒。
- 版本 `0002` 讓資料庫保護人工輸入：比對鍵 `name_key`、`alias_key` 由資料庫自動產生（去頭尾空白、轉小寫），名字不分大小寫不能重複；信箱格式由資料庫檢查；別名必須指到存在的人，改名時跟著改。

### 考慮過的替代方案

- **維持每次匯入整份取代**：Excel 保有完整歷史，但每天多一個檔案、容易選錯而覆蓋。
- **視窗另設「更新信箱」按鈕**：不需 SQL，但仍要維護 Excel 這份副本；使用者偏好直接在資料庫改。

### 後果

- 信箱的唯一來源是資料庫；`信箱.xlsx` 不再被程式讀取。
- 人工 SQL 沒有程式的格式檢查，因此改由資料表約束擋下常見錯誤；更細的規則（例如別名不能和其他人的名字相同）仍靠比對時的處理。
- 維護信箱的人需要有 `mailbox` 寫入權限的帳號；異動不會自動留下歷史紀錄。

## English

### Context

ADR 0003 made the daily import also read `信箱.xlsx` and replace the stored people every time. The mailbox rarely changes, so choosing an extra file each day adds no value and risks overwriting people with the wrong file. The user prefers to maintain it with SQL.

### Decision

- `mailbox.person` and `mailbox.alias` are maintained directly in the database (for example with pgAdmin) and are no longer imported from Excel.
- The daily import reads only `每日更新.xlsx`, never changes `mailbox`, and uses it only to match FC names; an empty mailbox is reported.
- Version `0002` protects manual input: matching keys `name_key` and `alias_key` are generated by the database (trimmed, lowercase), names are unique ignoring case, email format is checked by the database, and aliases must reference an existing person and follow renames.

### Alternatives considered

- **Keep replacing people on every import**: Excel keeps a full copy, but adds a daily file and risks overwriting with the wrong one.
- **A separate "update mailbox" button**: no SQL needed, but the Excel copy still has to be maintained; the user prefers editing the database.

### Consequences

- The database is the only mailbox source; the program no longer reads `信箱.xlsx`.
- Manual SQL bypasses program validation, so table constraints catch common mistakes; finer rules (such as an alias equal to another person's name) still rely on matching behavior.
- Mailbox maintainers need an account with write access to `mailbox`; changes keep no automatic history.

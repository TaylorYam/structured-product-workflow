# 核對規則：Nomura DACN 中文產品說明書與投資人須知

- 文件側：[Nomura DACN 範本規格](../templates/nomura-zh-dacn.md)（`nomura-zh-dacn-pd`）、[Nomura DACN 投資人須知範本規格](../templates/nomura-zh-dacn-iis.md)（`nomura-zh-dacn-iis`）
- 下單側：參考條件表，見[參考條件表格式](../order-formats/reference-sheet.md)與 [Nomura DACN 下單資料格式](../order-formats/nomura-dacn-reference.md)
- 商品：DACN（workflow ADR 0030、#366、#367）；開放順序 Nomura → SG → DBS → Natixis，本文件是 Nomura（workflow #368）
- 狀態：規格；實作另開 PR（workflow #368）。核對範圍以開發者凍結的螢光標記為準；**作業人員獨立標記先略過，2026-10-30 使用者決定**（§7）
- 標「待使用者確認」的是暫定的保守做法（轉人工覆核、不放行、不臆測），詳見本機疑慮記錄（DACN-368-01～08）；使用者回覆後再更新本文件與實作
- 本文件只寫和 [Nomura 核對規則](nomura-check-rules.md)（FCN）不同或 DACN 特有的部分。沒提到的（審查標準、固定警語、受託機構名稱與負責人、發行機構／保證機構／總代理人名稱、信用評等、幣別、費率、最低金額、受理申購日、刊印日期、價格推算、KO／KI／記憶式／標的數的內部一致、日期表、連結標的公司介紹、開始受理贖回日寫法）照 Nomura FCN

## 1. 範圍

- 只支援現行版範本（範本規格 §1）；辨識得出是 Nomura DACN、但現行版固定寫法對不上或交易日早於 2026-06-01 → 不支援的範本版本，轉人工覆核、不能人工放行（待使用者確認，詳見本機疑慮記錄）。
- 依第 7 項的每日計息公式（實際日數／總日數）辨識商品家族，不靠標題（workflow #366 決定 10）；Nomura FCN 與 DACN 範本互斥（範本規格 §8）。辨識結果和參考條件表 Product 不一致時轉人工覆核。
- 沒有樣本的型態（KO 每期觀察、非記憶式、單一標的、KI 每日／每期觀察、非美元、保證期數或 Non-Call ≠ 1）→ 轉人工覆核，錯訊寫「待樣本驗證」（§3.1；待使用者確認，詳見本機疑慮記錄）。KI 每期觀察的 DACN（MKI）另由 workflow #386 處理，本範本照轉人工。
- 兩份都通過或人工放行才打 `TS`／`IIS` 的 `V` 並回填（ADR 0007）。

## 2. 不核對的項目

- 照 Nomura FCN §2。
- **每日計息的計算**：實際日數 n_t、總日數 N_t、各期配息金額、配息日（workflow #366 不在範圍內；ADR 0030 不追蹤每日計息）。n_t、N_t 只核對定義文字（辨識時的固定寫法，範本規格 §2.1）。
- 第 7 項開頭與第 11 項 (6) 對 KO 那一期配息支付日的說法（兩處不一致，範本規格 §2.2；待使用者確認，詳見本機疑慮記錄）。
- 第 7 項 `觀察期間：` 定義、第 11 項 (6) 配息日的說明文字。
- 第 14 項基本假設 (ii) `Actual/360`（和配息公式無關；待使用者確認，詳見本機疑慮記錄）。
- 第 14 項情境三、四（同 FCN 2026-10-15 決定）。DACN 情境三的利息沒算第 1 期保證、進位不一致（範本規格 §2.2），一併不核對；情境三金額旁的幣別仍照 FCN 核對（Issue #316）。
- 第 16 項 `以計價幣別保障本金` 句（同 FCN 不核對；待使用者確認，詳見本機疑慮記錄）。
- 投資人須知的 `每單位面額×100%`（說明書寫 `每單位商品面額×100%`，只差兩字）。

## 3. 核對規則

### 3.1 樣態與分流

| 檢查 | 規則 |
|---|---|
| 開放 | `[auto_check_products]` 的 `DACN` 加 `NOMURA`（實作 PR）；沒開放的上手照不支援樣態轉人工 |
| 範本版本 | 寫法和現行版不同、或交易日早於 2026-06-01 → 不支援的範本版本（`template.detect`，原因 `template_unsupported`），錯訊列出缺的特徵 |
| 商品種類一致 | 辨識到的範本商品家族 ≠ Product → 轉人工覆核（共用 `template.product_family`）；Product 空白視為 FCN，所以 DACN 說明書配上 Product 空白的列也轉人工 |
| 沒有樣本的型態 | 說明書讀出的型態不是「KO 每日觀察＋記憶式、多標的、KI 無或到期觀察、美元、保證期數 1、Non-Call 1」→ 轉人工覆核（`doc.template_variant`），錯訊寫出哪一項「待樣本驗證」 |

### 3.2 參考條件表欄位（共用 `rules/reference.py`、`backfill.py`）

| 標準欄位 | 規則 | DACN 差異 |
|---|---|---|
| 商品代號、ISIN、幣別、面額、各日期、天期、K／KO／KI %、KO／KI 型態、記憶式、標的、各標的價格、最低金額、比價日 | 共用 `field.*`、`backfill.*` | 同 Nomura FCN |
| `coupon_pa_pct` | 共用 `field.coupon_pa_pct` | 主來源改成第 7 項 `年化配息率： X%`（FCN 是情境年化報酬率）；和 `Coupon p.a. (%)` 依說明書顯示位數比 |
| `coupon_barrier_pct` | 新共用規則 `field.coupon_barrier_pct`（§3.4） | 第一次核對參考條件表「配息門檻(%)」 |
| Non-Call | 共用 `field.first_callable_period`＋`field.non_call_product` | 同 FCN D 型；DACN Non-Call ≥ 1（`PRODUCT_RULES`）；另核 = 保證期數（§3.5） |

### 3.3 年利率

| 檢查 | 規則 |
|---|---|
| 主來源 | 第 7 項 `年化配息率： X%`；剛好一處，讀不到或多處 → 轉人工覆核 |
| 第 15 項 (1) | `年化報酬率：就第一個配息日而言: X1%。就其他配息日而言: X2% × 實際日數/總日數。` 的 X1、X2 = 主來源（各一筆，`doc.coupon_mentions`）；句型不同 → 辨識已攔下 |
| 第 14 項設定參數 | `年化配息率` `X%` = 主來源（共用 `scenario.params`，出處代號 `scenario_coupon_pa`） |
| 情境一 | `本情境中年化報酬率為Y%` 的 Y = 主來源（共用 `scenario.params`，`scenario_annualized_return`，依顯示位數比） |
| 情境二 | Y = 主來源 ×（g + P% ×（T − g））÷ T，四捨五入（half-up）到 2 位後完全相等；g = 保證期數（§3.5）、T = 天期、P = 情境二 `“實際日數/總日數“是P%`（`doc.scenario_return`）；P、g、T 任一讀不到 → 轉人工覆核 |
| 每期配息率 | 範本沒有（只寫 `年化配息率/12`）：FCN 的 `derive.monthly_coupon` 不適用 |

### 3.4 配息門檻（新共用規則，所有上手的 DACN 共用）

說明書配息門檻 `coupon_barrier_pct` 由各上手 parser 交出；Nomura 由第 7 項實際日數定義推得（`其各自執行價` → = `strike_pct`，範本規格 §4.1）。

| 參考條件表 | 規則 |
|---|---|
| 有「配息門檻(%)」欄、該列有數字 | 說明書配息門檻 = 表上值（依說明書顯示位數四捨五入後比，同 K%） |
| 有這欄、該列空白或 `-` | 轉人工覆核（DACN 一定要有值，ADR 0030） |
| 沒有這欄（舊 Excel） | 說明書配息門檻 = 表上 `K(%)`（workflow ADR 0030、#366 決定 3）；結果註明「表上沒有配息門檻欄，和 K(%) 比」 |
| 說明書讀不到 | 轉人工覆核 |

只在參考條件表 Product 是要有配息門檻的商品（`PRODUCT_RULES` 的 `has_coupon_barrier`：DACN）時執行；其他商品不產生結果。投資人須知沒有配息門檻，不核對。

### 3.5 保證期數

| 檢查 | 規則 |
|---|---|
| 主來源 | 第 7 項配息公式 `(i)就第一個配息日而言` → 保證期數 1；其他寫法 → 辨識已攔下（不支援的範本版本） |
| = Non-Call | 保證期數 = 第 7 項 KO 起日對到的日期表期別（`first_callable_period`）；不同 → 不一致（`doc.guaranteed_periods`） |

### 3.6 說明書內部交叉驗證

照 Nomura FCN §3.5（商品代號第 2 處、ISIN、名稱、幣別、期數、KO 觀察方式、Non-Call、記憶式、KI、標的數、日期表、到期贖回 100%）；名稱的英文第一章第 1 項寫法 `Nomura International Funding Pte. Ltd. {天期}-Month {CCY} Autocall Daily Range Accrual Notes {記憶式}linked to {標的}(unsecured)`。FCN 專屬的每期配息率（`derive.monthly_coupon`）不適用。

### 3.7 審查標準

照 Nomura FCN（`issuer.nomura`）。只有**商品名稱樣板**不同：設定 `[issuer.nomura.product_names.DACN]`（參考條件表 Product 是 DACN 時用，同 Super Bull 的做法）：

- 中文：`Nomura International Funding Pte. Ltd.發行{tenor}個月{ccy_zh}計價每日計息({memory_zh}自動提前出場){underlying_zh}結構型商品(無擔保)`
- 英文：`{tenor}-Month {ccy} Autocall Daily Range Accrual Notes {memory_en}linked to {underlying_en} issued by Nomura International Funding Pte. Ltd. (unsecured)`
- `memory_*`、`single_*`、`basket_*`、括號與空白的比對方式同 FCN 樣板；投資人須知同一樣板。

### 3.8 情境分析（第 14 項）

| 檢查 | 規則 |
|---|---|
| 設定參數 | 年期、面額、發行價格、投資金額算式（面額 × 發行價格 × 投資單位數）照 FCN；`年化配息率` = 第 7 項（§3.3） |
| 百分比表 | 照 FCN（每列 = 標的表表頭 %、列數 = 標的數） |
| 情境一、二 | §3.3 |
| 情境三、四 | 不核對（§2） |

### 3.9 投資人須知

照[投資人須知核對規則](iis-check-rules.md) §3 的 Nomura 欄；不同的地方：

| 檢查點 | DACN |
|---|---|
| B6 名稱 | = 說明書封面名稱（DACN 樣板） |
| B16 每期配息率 | 不適用（範本沒有）；改核年利率：第三 1. `年化配息率：X%` = 參考條件表 `Coupon p.a. (%)`（共用 `field.coupon_pa_pct`）、= 說明書第 7 項（`iis.coupon_pa_term_sheet`） |
| 配息公式 | 第三 1. 的 (i)(ii) 固定寫法（辨識時逐字比對，範本規格 §3） |
| KO、記憶式、KI、D 型 KO 起日、標的名稱、受理贖回文字 | 照 Nomura FCN |

## 4. 判定原則

同 Nomura FCN §4：必核欄位抓不到、抓到多個不同值、或寫法不在範本規格內，一律轉人工覆核。配息門檻、保證期數都由明確的固定寫法推得（Issue #297 的原則），不由關鍵字有無推測。

## 5. 探勘比對結果（2026-10-30）

探勘腳本（本機 `data/tmp/dacn_nomura/scripts/`：`explore_fcn_parser.py`、`dims.py`、`compare.py`）對 11 份說明書與投資人須知逐項比對舊總表（Product = DACN、TDCC 前三碼 156）與說明書內部一致性：

| 範圍 | 結果 |
|---|---|
| 現行 Nomura FCN parser 讀 DACN | 說明書除配息相關 5 個欄位（每期配息率 3 處、情境年化報酬率當年利率）以外全部讀得到；投資人須知只差每期配息率。11 份說明書與投資人須知都被判為範本不符（沒有被 FCN 範本誤判） |
| 參考條件表 | 代號、幣別、面額、各日期、天期、K／KO／KI %、KO／KI 型態、記憶式、Non-Call、比價日、各標的進場價與執行價、年利率全部一致。差異：1 份兩檔標的交易所碼不同（DACN-368-07）；5 格年利率是文字（DACN-367-01，其中 4 份在樣本內） |
| 型態 | 11 份同一範本版本；全部美元、KO 每日＋記憶式、Non-Call 1、保證 1 期、3～5 檔標的；KI 無 8 份、到期觀察 3 份；1 份標的是 ETF |
| 每日計息固定寫法 | 配息公式、實際日數、總日數、中斷日剔除句、第 15 項 (1) 句型、情境一／二假設句：11 份逐字相同 |
| 年利率各出處 | 第 7 項 = 第 14 項設定參數 = 第 15 項兩處 = 情境一 Y（11 份） |
| 情境二 | 11 份 Y = 年化配息率 ×（1 + 50% ×（T − 1））÷ T 四捨五入到 2 位，完全相等 |
| 情境三 | 利息沒算第 1 期保證、進位不一致（DACN-368-04）→ 不核對 |

## 6. 試跑預期（實作 PR 的驗收）

以私人雲端倉庫的 11 份樣本、舊總表整理的參考條件表（加 `配息門檻(%)` 欄 = `K(%)` 與不加兩種）在本機跑完整核對：

- 全部辨識成 `nomura-zh-dacn-pd`／`nomura-zh-dacn-iis`；沒有一份被 Nomura FCN 範本認走。
- 年利率是文字的 4 份：`Coupon p.a. (%)` 轉人工覆核（表上資料問題）；整理成數字後通過。
- 兩檔交易所碼不同的那份：標的判不一致（表上資料問題）。
- 其他：說明書與投資人須知全部通過並回填（ISIN、發行日、比價日）；配息門檻沒有欄時和 K% 比、有欄時和欄比都通過；改錯配息門檻時判不一致。
- Nomura FCN 與其他上手既有測試、本機真實樣本結果不變（FCN 辨識多一個條件，FCN 樣本都沒有每日計息公式）。

標記外、刻意不核對的段落見 §2。每條新規則實作時要有合成反例，特別是「正式條款正確、但其他出處錯」：第 7 項年化配息率正確、第 15 項其中一處或設定參數或情境一錯；情境二年化報酬率錯；實際日數定義改成別的價格（→ 不支援的範本版本）；配息公式改成保證兩期（→ 不支援）；KO 起日改到第 2 期（Non-Call 2 ≠ 保證期數 1）；參考條件表配息門檻 ≠ K%；配息門檻欄存在但空白；表上沒有配息門檻欄；Product 是 FCN 但文件是 DACN（及反過來）；FCN 說明書英文名稱誤寫成 DACN（兩邊都不符）；DACN 說明書英文名稱誤寫成 FCN（不被 FCN 認走）；交易日早於 2026-06-01；投資人須知年化配息率和說明書不同。

## 繁體中文

以下尚未決定，不應由 Agent 當作既定需求：

- 起單與建檔的正式確認時點、Order 修訂優先順序及人工確認方式。各家 Order 格式的第一版讀法已決定：以我方 `(Order)` 原信為準、規則式不用 AI（[#40](https://github.com/TaylorYam/structured-product-workflow/issues/40)）；上手回覆信是否比對待定。Citi 的 Non Callable Periods 已確認統一 +1（2026-10-20）。2026-10-21 起改讀起單建檔、不再讀信（#97、[ADR 0010](adr/0010-order-terms-from-daily-order-sheet.md)），上述讀信規則與上手回覆信比對不再適用。
- TDCC 取得時點、資料夾結構、候選附件配對與正式版本選擇規則。候選配對與版本選擇已照 [README](../README.md)「TS／IIS 批次準備」實作（#5）；TDCC 由起單建檔帶入（#97、[ADR 0010](adr/0010-order-terms-from-daily-order-sheet.md)）。
- 掃描文件處理、範本及座標解析相容性。Word 轉檔工具已選 Microsoft Word（[ADR 0002](adr/0002-word-to-pdf-with-microsoft-word.md)）。
- 回填 Excel 的實際目的地、庫存匯入由誰執行、總表結構與讀取時點。已不適用：庫存總表不再使用，商品資料改由交易明細、起單資料與股價建立（[ADR 0006](adr/0006-new-product-data-from-order.md)）；核對結果寫回資料庫（[ADR 0013](adr/0013-check-from-database.md)）。
- 自動寄出的時機與條件、重複寄送防護、寄送紀錄與不確定結果的處理。第一版寄信草稿已決定（傳統版 Outlook COM、只建草稿、FC 對照與郵件欄位），見 [#29](https://github.com/TaylorYam/structured-product-workflow/issues/29)。
- PostgreSQL 已選定，本機開發後目標為公司伺服器協作。第一階段的資料範圍、schema 分法與版本管理方式見 [ADR 0003](adr/0003-minimal-fcn-database.md)。仍待定：主要版本、正式主機與 IT 核准、共享服務介面、權限、備份還原與保存期限。狀態名稱已由 [ADR 0019](adr/0019-progress-step-records-and-lifecycle-events.md) 決定（作業進度、存續狀態）。見 [資料庫與部署](database-and-deployment.md)。
- FCN_Stepdown 等其他商品的規則與驗證範圍。CLI 跨專案契約已不需要：核對專案決定併入本專案（[ADR 0005](adr/0005-merge-checker-into-workflow.md)）。EXPRESS FCN 已決定（[ADR 0027](adr/0027-fcn-express.md)、#301）：和 FCN 共用流程與核對規則，依上手＋商品種類開放自動核對。Super Bull 已決定（[ADR 0028](adr/0028-super-bull.md)、#309）：沿用 FCN 的流程與欄位，自動核對依 BNP → CA → HSBC 開放。BEN 已決定（[ADR 0029](adr/0029-ben.md)、#372）：沿用 Super Bull 的欄位放法、加參與率，自動核對依 HSBC → MS → CA 開放。未決：Lookback BEN 已算出回顧期初價格之後，回顧結束日要不要開放修改、改了之後執行價怎麼回復（#374；目前一律擋）。DACN 已決定（[ADR 0030](adr/0030-dacn.md)、#366）：沿用 FCN 的流程，多存配息門檻，自動核對依 Nomura → SG → DBS → Natixis 開放。
- 新商品資料流程（[ADR 0006](adr/0006-new-product-data-from-order.md)）：股價範本、單位面額、Order 缺最終比價日／到期日已決定（[ADR 0008](adr/0008-daily-prices-denomination-and-order-dates.md)）。仍待定：股價範本改成指定日期後怎麼對交易日。港股補進交易所假日表已決定（[ADR 0020](adr/0020-close-prices-and-observation-rules.md)）。核對完寫回資料庫失敗時的處理已決定（[ADR 0013](adr/0013-check-from-database.md)）。
- 正式 Order 歸一化第一版採規則式、不用 AI（#40）；範本中的 AI 指輔助開發，並不代表 runtime 必須使用 AI。
- 自算風險等級的指數清單（[ADR 0023](adr/0023-self-calculated-risk-level.md)、#238）：已決定（#252）。指數本身不能連結，指數清單是空的；ETF 和指數一樣 3 分，ETF 清單取自「ELN可連結標的白名單」，放在 `config/risk_level.toml`。

新增最小切片建議：本機 PostgreSQL＋虛構案件／版本資料＋一次核對結果入庫：已實作（[ADR 0003](adr/0003-minimal-fcn-database.md)、[ADR 0013](adr/0013-check-from-database.md)）。歷史分析資料盤點另待確認；庫存 Excel 已不再是資料來源（ADR 0006）。

建議開發順序：驗證 Order／附件樣本與商品身分 → 文件準備及核對串接 → 歸檔與庫存 → 郵件草稿 → 評估自動寄送。前四項已實作（起單資料、準備與核對、放回、寄信草稿；「庫存」改為資料庫，ADR 0006）；自動寄送仍待評估。

## English

Unresolved items, not established requirements:

- Formal confirmation points for placement/booking, Order revision precedence, and human confirmation. The first issuer-format reading is decided: our original `(Order)` email is authoritative and parsing is rule-based without AI ([#40](https://github.com/TaylorYam/structured-product-workflow/issues/40)); whether to compare issuer replies remains open. Citi's Non Callable Periods is confirmed to shift by +1 (2026-10-20). From 2026-10-21 terms are read from the daily order sheet instead of emails (#97, [ADR 0010](adr/0010-order-terms-from-daily-order-sheet.md)), so these email rules and the issuer-reply question no longer apply.
- TDCC availability, folder hierarchy, attachment matching, and official-version selection. Attachment matching and version selection are implemented as described in the [README](../README.md) section on TS/IIS batch preparation (#5); the TDCC comes from the daily order sheet (#97, [ADR 0010](adr/0010-order-terms-from-daily-order-sheet.md)).
- Scanned documents, template and coordinate compatibility. Word conversion uses Microsoft Word ([ADR 0002](adr/0002-word-to-pdf-with-microsoft-word.md)).
- Actual Excel writeback destination, inventory import ownership, master structure, and read timing. No longer applicable: the inventory master is not used, product data is built from trade rows, the order sheet, and prices ([ADR 0006](adr/0006-new-product-data-from-order.md)); check results are written back to the database ([ADR 0013](adr/0013-check-from-database.md)).
- When and under what conditions to send automatically, duplicate prevention, send records, and uncertain outcomes. The first mail-draft version is decided (classic Outlook COM, drafts only, FC mapping, and email columns); see [#29](https://github.com/TaylorYam/structured-product-workflow/issues/29).
- PostgreSQL is selected, starting locally and targeting company-server collaboration. First-phase scope, schema split, and schema versioning are in [ADR 0003](adr/0003-minimal-fcn-database.md). Open: major version, production host/IT approval, shared-service interface, access, backup/restore, and retention. Status naming is decided by [ADR 0019](adr/0019-progress-step-records-and-lifecycle-events.md) (workflow progress and lifecycle status). See [database and deployment](database-and-deployment.md).
- Rules and validation scope for FCN_Stepdown and other products. A cross-project CLI contract is no longer needed: the checker will be merged into this repository ([ADR 0005](adr/0005-merge-checker-into-workflow.md)). EXPRESS FCN is decided ([ADR 0027](adr/0027-fcn-express.md), #301): it shares the FCN workflow and checking rules, with automatic checking opened per issuer and product type. Super Bull is decided ([ADR 0028](adr/0028-super-bull.md), #309): it reuses the FCN workflow and fields, with automatic checking opened for BNP, then CA and HSBC. BEN is decided ([ADR 0029](adr/0029-ben.md), #372): it reuses Super Bull's field layout plus a participation rate, with automatic checking opened for HSBC, then MS and CA. Open: once a lookback BEN's lookback initial prices are computed, whether its lookback end date may change and how the strike would be restored (#374; currently always blocked). DACN is decided ([ADR 0030](adr/0030-dacn.md), #366): it follows the FCN workflow with an extra coupon barrier, with automatic checking opened for Nomura, SG, DBS, then Natixis.
- New product data flow ([ADR 0006](adr/0006-new-product-data-from-order.md)): the price template, denomination, and Orders missing the final valuation or maturity date are decided ([ADR 0008](adr/0008-daily-prices-denomination-and-order-dates.md)). Still open: trade-date matching once the price template names the date. Adding Hong Kong to the exchange holiday calendar is decided ([ADR 0020](adr/0020-close-prices-and-observation-rules.md)). Handling a failed database write-back after checking is decided ([ADR 0013](adr/0013-check-from-database.md)).
- The first Order normalization is rule-based without AI (#40). AI in the template means development assistance, not a runtime requirement.
- The index list for the self-calculated risk level ([ADR 0023](adr/0023-self-calculated-risk-level.md), #238): decided (#252). Indices themselves cannot be linked, so the index list is empty; ETFs score 3 like indices, and the ETF list comes from 「ELN可連結標的白名單」 in `config/risk_level.toml`.

Additional recommended slice: local PostgreSQL, synthetic cases/version records, and one persisted check run: implemented ([ADR 0003](adr/0003-minimal-fcn-database.md), [ADR 0013](adr/0013-check-from-database.md)). The historical-source inventory still needs a separate decision; the inventory Excel is no longer a data source (ADR 0006).

Suggested sequence: validate Order/attachment samples and product identity; document preparation/checker integration; archives/inventory; email drafts; evaluate automatic sending. The first four are implemented (order sheet, preparation and checking, return, mail drafts; "inventory" became the database, ADR 0006); automatic sending is still to be evaluated.
